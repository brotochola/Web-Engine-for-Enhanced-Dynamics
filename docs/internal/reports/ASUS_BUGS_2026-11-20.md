## Task 1: mipmaps in Predator (E-204), rejected (R-1700)

The coordinator's probe (`kmip.mjs`) flipped Predator's own `renderer.autoGenerateMipmaps` line, off against on. It ran
twice, 4 pairs, GPU time a frame by glFrameRecorder `--gpu-draws`:

| view | off | on | change |
| --- | --- | --- | --- |
| day, default zoom | 10.95 ms | 11.02 ms | +0.6 % |
| day, zoom 0.216 | 11.43 ms | 10.60 ms | -7.2 % |
| night, light3d | 28.37 ms | 28.12 ms | -0.9 % |

- **Where mipmaps act:** only on the sprite program. Zoomed out it drops 28 % (3.36 -> 2.43 ms), and the tileset and
  light passes stay flat. At night the lamps' map grows 12 % and eats the G-buffer's gain.
- **The pictures:** no bleeding between atlas frames and no halo. But Predator's pixel art blurs (the crowd reads as
  brown dots) and tree shadows smear into grey patches.
- **Verdict:** the bar was -3 % in all three views. It cleared only zoomed out, so Predator keeps mipmaps off.

## Task 2: fixed

Each fix has a behavioural test that fails on `bugs/base`, unless the entry says otherwise.

### N-81: a paused world (time scale 0) makes no body (R-1701)

- **Cause:** the physics host skipped a frame whose scaled dt was 0 whole. Spawns, teleports, commands and joints made
  in a hitstop reached Box2D only at the next step: missing from ray, AABB and overlap queries, and teleports missing
  from the spatial grid's movers path.
- **Fix:** such a frame calls `weedjsSyncPaused` (`weedjsPost.js`):
  - syncBodies, drainCommands and syncJoints, then the six query services;
  - when anything changed, the previous pose, the children, the pose, and a moved list holding the teleports alone.
  - The step path is untouched.
- **Test:** `pausedWorldSync.test.js` runs the host's frame and the paused sync as shipped.
- **Commits:** 21f915a0.

### N-247: Keyboard.isPressed lower-cased the key name on every call (R-1702)

- **Cause:** every isPressed and isDown made a string (341 B a frame in burningBoxes, from the original heap pass).
- **Fix:** each name is resolved once into a Map, cleared by initialize and capped at 512 names. `isDown('constructor')`
  no longer resolves to Object's function.
- **Test:** `keyboard.test.js`. Over 3 frames of 5 names, toLowerCase ran 15 times before and runs 4 now. The heap
  itself was not re-measured.
- **Commits:** 31cbc600.

### N-161: the scoreboard's audioStorm row could not decide (R-1703)

- **Cause:** its load key was BODY_COUNT in a scene with no bodies (0 on both sides), and logic0 sat under the floor.
- **Fix:** one AudioStormDriver for each 100 plays a tick, marked `reportMarkActive`, so the row's load key is logic0's
  MARK_ACTIVE. The default is 48 000 plays.
- **Measured on the ASUS:** logic0's own work grows about 0.19 ms a 1000 plays, linearly: 0.33 ms at the old 1200,
  9.3 to 9.5 ms at 48 000.
- **Test:** `engineFeatureCatalog.test.js`: every row's load keys are ones extractMetrics publishes.
- **Commits:** 752f2353, 703b8504.

### N-251: a worktree's bundles differed from the main folder's (R-1704)

- **"Cannot run" did not reproduce:** the build ran in a plain worktree and in one with a junctioned node_modules. The
  bundles differed, for two reasons:
  - atlasCache.js's bare `import.meta.url`, which webpack writes as the builder's own `file://` path, so every
    published bundle carried the folder it was built in;
  - webpack and Node followed the node_modules junction into module identifiers (the deterministic ids moved) and
    into the debug CSS asset's hash.
- **Fix:** `MODULE_URL` is `''` in a webpack build. `symlinks: false` for resolve and resolveLoader in the three webpack
  configs (the ESM config now takes the UMD one's resolveLoader). buildBundle runs webpack with `--preserve-symlinks`
  and `--preserve-symlinks-main`.
- **Checked:** after the fix, a junctioned worktree and the main folder built all 12 `dist` files byte for byte alike.
  A tree without symlinks builds as before, minus the path (about 0.1 KB a bundle).
- **Test:** `bundleWorktreeBuild.test.js`.
- **Commits:** 33d93175, 0b577a9f.

### N-254: a scene that failed while booting cost about 10 minutes of the queue (R-1705)

- **Cause:** a worker that dies outside the engine's handlers shows no fatal overlay, only the page's uncaught error.
  The runner waited out its watchdog (warm-up + window + 5 min), and measureLib then ran it again.
- **Fix:** `tests/bench/bootWatch.mjs`, raced with loadScene by the page, fails the boot 10 s after the page's first
  uncaught error or unhandled rejection when the scene has still not booted. A scene that boots through a stray error
  is not failed. The runner exits 4 on a boot failure, and runIntegratedWithRetry does not run it again.
- **Fixture:** `bootFailureScene` (stress scene), whose entity never finishes loading in a browser worker and throws
  uncaught.
- **Checked:** on `bugs/base` the fixture was still running when cut at 60 s; now it exits 4 in 15 s, with one run.
- **Test:** `bootWatch.test.js`.
- **Commits:** cb0b5621, 2eca13c3, 1d4e5111 (the fixture throws in browser workers only, so Node's demosQuiet stays
  quiet).

### N-255: pruneTestResults removed the capacity history (R-1706)

### N-325 step 1: entries past maxEntitiesPerCell are counted and warned (R-1707); step 2 left

- **Fix:** every grid pass counts the entries past a cell's cap: the two rebuilds in the else of their cap test, the

- **Cost:** rebuildOwnedRowsMicrobench 2.216 -> 2.197 ms a frame (noise), same checksum.
- **Test:** in `spatialGridMovers.test.js` the rewrite's count equals the full rebuild's, frame by frame.
- **Left (step 2):** Predator's cap of 32 against its crowds, with spatial's cost measured in Predator.
- **Commits:** 20ba14c4.
